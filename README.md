### ① 3段階の商品（原則、増やさない）

## FAQ（05「安心のために」内）の追加・編集手順

FAQは 05「安心のために」ブロックの後半にあります（前半はデータの取り扱い3行リスト）。`<details>` / `<summary>` によるアコーディオンです（**JSゼロ**。開閉はブラウザ標準機能）。現在は5問（詳しくない方向け／対応エリア／データの扱い／営業しない／途中でやめられる）。

  <div class="faq-item__body">
    <p>回答をここに。他セクションへは <a href="#pricing">アンカーリンク</a> で誘導できます。</p>

`<div class="faq">` の中に上記を追加・並べ替えするだけです。「Q」バッジと開閉の矢印はCSSが自動で付けます。

## デザイン・実装メモ

- **配色**：**ロゴのブランドカラーに統一**。ロゴ原色は 紺 `#0B3A63` ／ 青緑 `#0A98A8` ／ 黄緑 `#8BC53F`。
  - `--deep: #0b3a63`（ロゴの紺そのまま）＝ヒーロー・最終CTA・フッターの帯
  - `--teal: #086a76`（青緑をテキスト用に暗くしたもの）＝リンク・ラベル・アイコン。**原色 `#0A98A8` は白地で4.5:1に届かない**ため、小さな文字に使う色は暗く調整している。原色は `--teal-bright` として図版・罫線用に保持
  - `--lime: #8bc53f`（黄緑の原色）＝図版専用。文字色には使わない
  - 面積比は 白62% ／ `--paper` 20% ／ `--deep` 16% ／ 鮮やかな色1%未満。派手なグラデ・紫系AIグラデは不使用
  - コントラストは全310テキスト要素をスクリプトで実測し、WCAG AA（4.5:1）未達は**LINEブランド指定色のボタン1件のみ**（`#06C755`＋白文字はLINEの規定のため変更不可）
- **フォント**：Noto Sans JP（本文16px以上）。微細なラベル・数字のみシステム等幅フォントで「Lab」らしさを付与。
- **レスポンシブ**：モバイルファースト単一カラム → `@media (min-width: 768px)` でPC多カラム。比較表は横スクロール（`overflow-x: auto`）。
- **CTA**：**主導線＝予約（TimeRex直リンク）／副＝LINE** に一本化。ヘッダー・ヒーロー主CTA・モバイル固定バーはすべて「30分、困りごとを話す」でTimeRexへ直行します（ヘッダーは520px未満で「30分相談する」にCSSのみで短縮：`.btn__wide` / `.btn__narrow`）。ヒーローではLINEをアウトライン化し、主CTA（白の塗り）を視覚的に上回らないようにしています。「無料」は売り文句ではなく条件として、主CTA直下に `.hero__terms`（無料・30分・オンライン）で小さく添えています。
- **ヒーローの見出し**：主語は「AIを使いたい」ではなく**お客様の仕事**です（「毎月くり返す書類仕事を、まず一つ、減らします。」）。強調下線 `.hero h1 .u` は `display:inline-block` で、囲んだ語（現在は「まず一つ」）が**語中で折り返さない**ようにしています。下線を付け替えるときは、途中で改行されない短い語句を選んでください。「提案書だけ渡して終わり／言われたものを作るだけ」の対比は見出しから降ろし、サブコピーに残しています。
- **ヒーローのモバイル圧縮**：390px幅で主CTAが初期表示に入るよう、`@media (max-width: 767px)` で余白・行間・アバター径・kickerサイズを圧縮しています（実測：ヒーロー高 679px、主CTA下端 550px＝ヘッダー64px込みで614px）。**主CTA下端はヘッダー込み700px以内**を維持してください。ヒーローの文章を増やす場合はこの数値が崩れていないか確認すること。
- **モバイル総高（7ブロック再編後）**：390px幅で **約11,840px**（旧10セクション時は約17,340px、約32%短縮）。1280px幅で約8,270px。横スクロールなし・ヒーロー主CTA下端593px（ヘッダー込み）。数値は全 `<details>` を閉じた状態でのPlaywright実測。折りたたみ内容を常時表示に戻すと総高は再び伸びます。
- **04「相談から実装まで」の構成**：旧「02 AI実装Labとは」と「08 ご支援の流れ」を統合。主役は **相談→診断→実装の3ステップ**（`.process` の3カード）で、旧「聞く→その場で形にする→使える状態にする」の趣旨は各カードの説明文に吸収しました（`.fde-callout`／`.fde-steps` の3ピルは廃止）。FDEという職種の説明は差別化の根拠として `.fde-note`（独立した注記カード）に3行で残しています。比較表は**3行**（実装／業務そのものの理解／支援の終わり方）に絞り、**常時表示のまま**——競合が明示していない差別化なので畳みません。「伴走の出口は自走」の一文（`.fde-closing__sub`）も維持。
- **想定と実測の区別**：旧CASE 01〜03（想定シナリオ）の数値は 01「減らせる業務」の業務一覧「具体例を見る」（`<details>`）内へ移し、数値横の `※想定`（`.assume`）注記を維持しています。実測は代表自身の1件のみで、03「実績と担当者」の先頭に `実測値` バッジ（`.case-badge.is-actual`、塗り）付きで常時表示。実績と誤認されるため、想定側から `※想定` 注記を外さないでください。
- **JS**：ゼロ。スムーススクロールは CSS `scroll-behavior: smooth`。ページ読み込み時のヒーロー段階表示もCSSアニメのみ。FAQ・業務一覧・経歴・料金の補足・お問い合わせフォームの折りたたみも、すべて `<details>` のブラウザ標準機能で実現（FAQは `.faq-item`、その他は共通の `.disclose`。いずれも `prefers-reduced-motion` に対応）。
- **顔写真**：`assets/profile.jpg` を2箇所で使用。ヒーローは56pxの円形（`.hero__avatar`）、06プロフィールは150pxの円形（`.profile__photo`）。差し替える場合は**正方形**（推奨640×640）を用意すれば `object-fit: cover` で自動的に円形に収まります。
- **経歴バッジ**（`.cred-badges`）と**技術スタック**（`.chip`）は別クラスです。前者は淡いティール地＋濃いティール文字、後者はネイビー地に白抜きで、意図的に見た目を分けています。
